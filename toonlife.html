Technical Deep Dive

Toonlife — a multiplayer cartoon city for Roblox

A multiplayer life-sim city for Roblox, built solo in 20 days. Players fish, run delivery jobs, shop for cars, and decorate homes in a persistent economy across a coastal world with traffic, pedestrians, animals, and day/night cycles. The technical challenge: getting a world this large to exist on Roblox at all — which drove a custom asset pipeline and exploit-resistant server systems.

Architecture

Client–Server Split

Roblox RemoteEvents / RemoteFunctions across ReplicatedStorage (shared logic), ServerScriptService (systems), and StarterPlayer (client). Server validates all economic actions; client renders and predicts.

Asset Pipeline

An 11,447-node pre-assembled Cartoon_City.glb is deconstructed into 681 modular pieces, each uploaded via Roblox Open Cloud and reconstructed in-world by exact transform. Sidesteps the ~200-mesh import ceiling and preserves instancing.

Living City

Life.server.luau drives 150 kinematic traffic cars, 30+ pedestrians, animals, and birds through a shared LOD scheduler (Agents.luau) that culls and tiers agents by distance — movement is CFrame-driven, no physics.

Persistence

DataStore-backed wallet, garage, fishing dex, and room designs. Every write is an idempotent UpdateAsync merge — a fast server-hop can never roll back a caught species, a purchased car, or earned cash.

UI System

UIKit.luau — a reusable component library: world markers, directional arrows, cash HUD, status cards. Data-driven minimap + full-screen map survive streaming; a settings panel exposes perf modes.

Build & Sync

Rojo watches src/ and live-syncs into Roblox Studio. A Python toolchain (42 scripts) turns raw GLB → layout.json → generated Luau data modules, with atomic writes that survive crashes mid-build.

Asset Pipeline Flow

A single 94 MB city model exceeds Roblox mesh-import limits and only collapses identical meshes sharing a MeshId. The pipeline deconstructs the monolith, moderates and uploads each piece, then rebuilds from exact world transforms — so 1,446 identical road tiles collapse to one draw call.

Cartoon_City.glb ──▶ build_layout.py ──▶ layout.json ──▶ Open Cloud ──▶ In-World 11,447 nodes walk scene graph 681 modules upload reconstruct 94 MB monolith accumulate world + asset_map per piece by transform transforms instanced │ │ │ ▼ ▼ ▼ coord convert run_moderation.py gen_rojo_sources.py glTF → Roblox AI visual audit 681 placed pieces rotation, not fail-closed: 10 → Luau data modules reflection unsafe assets → Rojo → Studio (curves must excluded; per-hash not mirror) stamps block re-upload

Living City Systems

Live in-engine — third-person play through downtown: moving traffic, signal-lit intersections, the streamed city & HUD, captured in Roblox Studio

Traffic AI

150 cars follow lanes kinematically with per-vehicle speed profiles, yield to pedestrians and players, and obey light-synced routing. CFrame-driven — no physics solver runs for the fleet.

Pedestrians & Animals

30+ NPCs with distance-based LOD — lightweight fallback rigs far away, full cartoon characters up close. Behavior cycles: idle, walking, sitting, posing. Roaming animals and birds add liveliness.

LOD Scheduler

Agents.luau runs one shared scheduler across all agents — far / mid / close tiers with crowd collision avoidance, culling distant agents so a fully populated city holds frame rate.

Day / Night

Dynamic lighting cycles: fresh daytime palette to neon-lit night, synced with traffic-light routing and ambient behavior shifts.

Streaming World

StreamingEnabled with a 3000-stud target radius and 256-stud minimum — the entire coastal city loads progressively with no monolithic load screen.

Instancing

Modular pieces sharing a MeshId collapse to a single draw call. Reconstructing from modules rather than importing the monolith is what makes the whole map renderable.

Performance & Safety

  • Server-authoritative economy — fishing reels, delivery payouts, and car purchases are all validated server-side. The client never decides a win.
  • Save-loss protection — idempotent UpdateAsync merges and monotonic max-merge on the fishing dex mean a fast rejoin can't roll back progress; race conditions resolve in the player's favor.
  • Latency compensation — GetNetworkPing + a reel grace window keep the fishing minigame fair across connection quality.
  • Exploit guards — min-travel-time requirements block teleport-to-payout; per-asset moderation hash stamps block re-uploading unsafe content under a new filename.
  • Content moderation gate — an AI visual audit runs on every asset before upload; the pipeline is fail-closed, auto-excluding 10 flagged assets (bars, nightclubs, flagged billboards).
  • Kinematic movement — 150 cars and 30+ NPCs move by CFrame rather than physics, keeping a fully populated city cheap.
  • Streaming + instancing — 3000-stud streaming radius and MeshId-shared instancing make a 4.5 GB asset library playable in-browser.
  • Atomic build writes — the Python pipeline writes layout and manifest files atomically so a crash mid-build never corrupts generated data.
📄

Key Modules

  • build_layout.py Pipeline — Walks the glTF scene graph, accumulates world transforms, converts glTF → Roblox coordinates (rotation, not reflection, validated against asymmetric road curves), and emits deterministic layout.json + asset_map.json.
  • gen_rojo_sources.py Pipeline — Turns the 681-piece layout into generated Luau data modules consumed by Rojo, reconstructing the city in-world by exact transform.
  • run_moderation.py Safety — AI visual audit per asset with fail-closed exclusion and per-hash pass/fail stamps to prevent re-upload exploits; a character allowlist auto-identifies rigs vs static props by GLB structure.
  • Life.server.luau Server — Drives the living city: 150-car traffic AI, 30+ pedestrians, animals, birds, and traffic-light routing.
  • Agents.luau Shared — One scheduler for all agents: far / mid / close LOD tiers, crowd collision avoidance, distance culling.
  • InventoryService Persistence — Idempotent UpdateAsync merge pattern that never overwrites newer data on a DataStore race.
  • UIKit.luau Client — Reusable UI components: world markers, directional arrows, cash HUD, status cards, data-driven map.
  • CityConfig.luau Config — Centralized game-tuning constants for the city, economy, and population systems.
