Architecture

AI Search Engine

User queries hit gpt-5-search-api with a built-in web search tool, returning structured JSON (title, author, tropes, URL). Results are cached in a 3-layer stack — in-process unstable_cache → Postgres SearchResultCache → OpenAI — and cut AI spend by ~95%.

Multi-Source Data Enrichment

Each book is joined against Open Library (ratings, shelves, series), Google Books (descriptions, ISBN, page counts), and Kaggle reviews (Kindle + Goodreads). Title-cleaning pipeline lifted match rate from ~40% to ~85%.

Self-Sustaining Content Loop

Every search saves ~10 books synchronously before response, triggers revalidatePath(), then pings IndexNow (Bing/Yandex/Naver) and Google sitemap. New pages appear in search engines within minutes.

Daily Automation

5 Vercel Cron jobs run nightly (02:00–04:00 UTC): aggregate (stats & trends) → featured → collections → books (enrichment) → authors (AI bios + photos from Open Library).

Self-Healing 404s

If a user hits a book slug not yet in the DB, the page falls back to SearchResultCache and creates the row on-the-fly. Combined with 60s ISR, this eliminated the race condition that produced 404s after fresh searches.

Geo-Aware Monetization

Edge proxy reads x-vercel-ip-country, sets a geo cookie, and a deterministic URL builder maps to 14 Amazon locales with the right affiliate tag. No AI-generated URLs — every external link is constructed server-side.

Engineering Challenges

Real problems hit in production and how I resolved them. Measured impact where possible.

  • Persistent 404s on freshly-searched books Race condition

    Problem — saveSearchBooksToDb ran inside after(), so the response returned before the book row existed. Users got 404 clicking their own search results.

    Fix — Moved save to be synchronous before response. Added a self-healing fallback that reads SearchResultCache and creates the row on-the-fly. Reduced ISR from 24h → 60s to prevent stale 404 caching.

    Result — +200ms search latency, 404 rate effectively zero.

  • Google Books quota exhaustion API limit

    Problem — Each search triggered ~100 cover-image calls, burning through the 1,000/day free quota in minutes during testing.

    Fix — Built a 3-layer cover cache (memory → Postgres → API), inserted Open Library as the primary source, added a batch endpoint with concurrency limit of 3.

    Result — ~100 → ~3 calls per search. Quota stopped being a constraint.

  • AI-hallucinated external URLs LLM trust

    Problem — GPT returned Goodreads / Amazon URLs that looked real but 404'd. Users left the site through broken affiliate links.

    Fix — Never trust LLM URLs. All Goodreads links are constructed as search queries (goodreads.com/search?q=…); Amazon links use a deterministic geo-aware builder with the affiliate tag.

    Result — 100% link reliability across all 14 locales.

  • Dual OpenAI API paths breaking on model swap Abstraction

    Problem — *-search-api uses Chat Completions, gpt-4o-mini uses Responses API with explicit web_search. Swapping models broke the parser.

    Fix — isChatSearchModel() detects the model at runtime and routes to the right path. Both paths normalize to a single RawSearchResponse. Model is one env var.

    Result — Hot-swappable models with zero code changes.

  • Connection-pool exhaustion during batch jobs Production

    Problem — Author cron + description backfill exceeded Supabase's MaxClientsInSessionMode, 500-ing live traffic.

    Fix — Switched batch loops to sequential execution with explicit cleanup, 1–4s API spacing, and connection_limit=3 on the Prisma pg adapter to stay under PgBouncer.

    Result — Stable pool usage during batch ops. Zero production impact since.

Key Modules

  • lib/save-search-books.ts Shared — Single save path shared by /api/search and the SSR /search route. Unified the sync vs async bug.
  • lib/openai-client.ts AI — isChatSearchModel() switches between Chat Completions and Responses API. Unified RawSearchResponse contract downstream.
  • lib/enrich-books.ts Data — Orchestrates Open Library → Google Books → Kaggle review joins. Skips already-enriched rows via enrichedAt timestamp, 1s rate-limit between API calls.
  • lib/clean-book-title.ts Data — Strips parenthetical series info and subtitle noise before Open Library queries. Lifted match rate from ~40% to ~85%.
  • lib/author-slug.ts Data — Normalizes name variants ("H.D. Carlton" ≡ "H. D. Carlton") into a canonical slug so books group correctly across 300+ authors.
  • lib/amazon-link.ts Monetization — Deterministic URL builder across 14 Amazon locales from the edge-proxy geo cookie. Never trusts AI output.
  • app/sitemap.ts SEO — Dynamic (force-dynamic) 1000+ URL sitemap including top 50 trending queries from the last 7 days of analytics.
